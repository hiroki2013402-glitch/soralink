# SoraLink

SoraLink is a responsive social photo/video sharing app built with React + TypeScript + Vite, Express, and Turso/libSQL. The app includes an OAuth login flow for Sennin Account, a home feed, 24-hour stories, user search, profile pages, profile editing, follows, likes, and notifications.

## Features

- Sennin Account OAuth login/logout (no local password database)
- Responsive blue/white UI with a mobile bottom navigation
- Image/video posts with captions and delete-own-post permission
- Direct image/video upload from the device; uploaded bytes are stored in Turso as 256 KiB BLOB chunks
- Uploaded media is served through an internal `/api/media/:id` route; new posts cannot use external media URLs
- Separate URL paths for `/page/login`, `/page/home`, `/page/search`, `/page/create`, `/page/notifications`, and `/page/profile`
- Clickable follower/following counts with user lists and profile navigation
- Stories that expire 24 hours after publication (expired rows are hidden automatically)
- Profile page with avatar, cover image, bio, website, posts, follower/following counts
- User search, follow/unfollow, like/unlike
- Notifications for new likes and follows
- Turso schema initialization and backward-compatible profile-column migrations
- Production static serving from the same Express process

## Requirements

- Node.js 20+
- A Turso database and auth token
- An OAuth application registered in Sennin Account
- Turso database and auth token; uploaded media is stored in Turso, so monitor database storage and read/write usage. Uploads are limited to 20 MB per file.

## Local setup

1. Copy `.env.example` to `.env`.
2. Fill in all required values below.
3. Install dependencies: `npm install`
4. Build: `npm run build`
5. Start production mode: `npm start`

For development with Vite hot reload, use `npm run dev`. Vite proxies `/api` requests to `http://localhost:3000`.

## Required environment variables

| Variable | Purpose |
|---|---|
| `COOKIE_SECRET` | Random secret, at least 32 characters |
| `TURSO_DATABASE_URL` | Turso database URL (`libsql://...`) |
| `TURSO_AUTH_TOKEN` | Turso auth token |
| `SENNIN_CLIENT_ID` | OAuth client ID from Sennin Account |
| `SENNIN_REDIRECT_URI` | Exact callback URL, usually `https://YOUR-SERVICE.onrender.com/api/auth/callback` |

Configure `APP_ORIGIN` to the public origin of the frontend/service. For a single Render web service, use the same Render URL, e.g. `https://YOUR-SERVICE.onrender.com`. The optional OAuth endpoints and client secret are documented in `.env.example`.

## Render deployment

Deploy this folder as a Node web service:

- **Build Command:** `npm install && npm run build`
- **Start Command:** `npm start`
- **Health check path:** `/api/health`

The server serves the built frontend from `dist` when it is present; this does not depend on `NODE_ENV`.

Add the environment variables in Render's Environment settings. Set `SENNIN_REDIRECT_URI` to the exact deployed callback URL and register that same URI in the Sennin Account OAuth app. Do not commit `.env` or database tokens.

## Media uploads and storage

Posts and stories are uploaded directly from the device; the UI no longer asks users to paste a media URL. The server checks allowed MIME types and file signatures, enforces a 20 MB limit, and stores the bytes in `media_chunks` as 256 KiB BLOB chunks in Turso. `media_assets` stores the metadata. `/api/media/:id` streams the stored file back to the browser. New posts accept only media IDs generated by this upload endpoint, and a user can only attach media they uploaded.

This keeps the app self-contained, but media can consume Turso storage and read/write quota quickly. For a large public social network, object storage such as S3-compatible storage is usually more economical; this version intentionally uses Turso as requested. Avatar and cover images can now be uploaded from the profile editor. The website field remains a normal profile link.

## Database behavior

On startup, the server creates missing tables and indexes. Existing `users` tables are migrated to add `cover_url`, `bio`, and `website` if those columns do not exist. Stories are hidden when `expires_at` is in the past; the database rows are retained for now and can be cleaned up by a scheduled task later.

## Troubleshooting

- `TURSO_DATABASE_URL と TURSO_AUTH_TOKEN を設定してください`: set both Render environment variables.
- OAuth callback error: verify client ID, redirect URI exact match, authorization/token/userinfo endpoints, and `APP_ORIGIN`.
- Upload errors: check that the file is a supported image/video, is no larger than 20 MB, and that Turso has sufficient storage and request quota.
- Images not appearing: verify that `/api/media/:id` returns the stored content and the media rows/chunks exist in Turso.
- `npm start` cannot find `dist-server/index.js`: run the build command successfully before starting.


## Structure

- `src/pages/`: route-aware page composition (`AppPage.tsx`) and the extracted `login/LoginPage.tsx`; URL routes are documented above
- `src/components/`: reusable UI pieces such as post composer, media post, and brand mark
- `src/lib/`: API client helpers
- `server/`: OAuth, session security, API routes, and database initialization

## Security notes

- OAuth state validation and PKCE remain enabled; session cookies are HttpOnly and SameSite=Lax.
- Helmet security headers and a restrictive Content Security Policy are enabled.
- API request bodies are size-limited and API routes have per-process rate limits.
- Uploads are authenticated, limited by file size and allowed media signatures, and ownership is checked before media can be attached to posts or profiles. Never commit `.env` or production secrets.
- The included rate limiter is in-memory and is not shared across multiple server instances; use a shared rate-limit store for horizontally scaled production deployments.

## UI direction

The feed uses a familiar social-network layout, with a neutral gray background, white cards, blue actions, a compact top bar, story strip, responsive navigation, and subtle motion. SoraLink retains its own name and logo rather than copying Facebook branding or assets.
